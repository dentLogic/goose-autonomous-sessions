# patches/

This directory holds the Goose Desktop integration patches — small, targeted
hooks that wire the autonomous controller into Goose's existing lifecycle.

## Status: pending a pinned Goose commit

Per the implementation spec (§35, §62, §64), the patches are **not** shipped
blindly. They will be generated against a **specific pinned Goose commit** so
that:

- the expected source context can be verified before patching,
- the resulting source can be validated after patching,
- the installer can refuse safely if the source has drifted.

## Planned integration points

These are the existing Goose Desktop files the v0.2 installer will patch
(signatures verified against the pinned commit at generation time):

| Responsibility              | Goose area                                        |
| --------------------------- | ------------------------------------------------- |
| Chat turn lifecycle         | `ui/desktop/src/hooks/useChatSession.ts`          |
| ACP session creation        | `ui/desktop/src/acp/sessions.ts`                   |
| ACP prompt submission       | `ui/desktop/src/acp/prompt.ts`                     |
| Usage/context notifications | `ui/desktop/src/acp/adapter/...`                   |
| Desktop navigation          | `ui/desktop/src/hooks/useNavigationSessions.ts`   |
| App events                  | `ui/desktop/src/constants/events.ts`              |
| Global Desktop settings     | `ui/desktop/src/utils/settings.ts`                |

Each patch will be a small, reviewable diff — never a rewrite. The autonomous
logic itself lives entirely in `src/autonomous/`; the patches only add the
lifecycle hooks that call into it:

```ts
// useChatSession.ts (illustrative — actual patch TBD against pinned commit)
autonomousController.onUserPrompt?.(...);
await submitToAcpSession(...);
await autonomousController.onTurnFinished?.(...);
```

## How to pin a Goose commit

```bash
cd /path/to/goose
git rev-parse HEAD           # record this in patches/PINNED_COMMIT
```

Once a commit is pinned, the patch files will be generated by running
`git diff` between the clean Goose source and the customized source, then
validated by re-applying them in CI.
